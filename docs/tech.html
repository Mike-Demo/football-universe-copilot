How Football Universe Copilot is built, what every piece is, and what it costs to run. ← Back to the live demo

The project is open source

All code is MIT-licensed (see LICENSE) and public at github.com/Mike-Demo/football-universe-copilot. Design language: Microsoft Fluent 2 (see Components & licenses for the credit). The demo site itself has no framework, no bundler and no tracking — the replay engine and the force-directed graph are hand-written vanilla JS on a canvas. The single third-party script is CO2.js (The Green Web Foundation), used only for the per-visit footer estimate on this page, computed locally from transferred bytes.

Data policy: every match, event and season in this project is synthetic — generated by seeded simulators in the repo (deterministic: same seed, same season). No real Premier League or WSL results, footage or feeds are used or redistributed. The universe graph (players/clubs/managers) is a small hand-authored seed of well-known historical connections.

Architecture

Synthetic events → Interpreter agent (stats, momentum, control-vs-chaos, threshold alerts) → GraphContext agent (BFS shortest paths, Brandes betweenness → "Kevin Bacon Score", verified connections only) → Narrator agent (grounded narration; Microsoft Phi-4-mini on Foundry when configured, deterministic template otherwise — every output labels its narration_source) → Personalizer agent (analyst / casual / player-focus / club-focus / Spanish renderings + a timed, machine-readable broadcast overlay, schema football-universe-overlay/v1). Agents hand off through one shared state object; the same agent classes run locally (pure Python, zero dependencies) and in Azure.

The season simulator

A seeded Poisson goals model over plausible synthetic club strength ratings simulates the full calendars — 380 Premier League matches and 132 Women's Super League matches — producing standings, form, points progressions and season narratives that are computed from the simulated results, never hand-written. In the browser, any fixture can be loaded and a deterministic event timeline (shots, passes, pressure, alerts) is generated from its simulated scoreline, so all 512 matches are watchable.

Running costs

The full breakdown is in infra/COSTS.md: every Azure service is pay-per-use with a $0 floor, the deployment sits under its own billing profile with a $10 budget alert, and the realistic total through judging is $0–2.

Data standard — FIFA Connect Data (FCD) v3.3

The hackathon mandates no data format, so we aligned our match data to the FIFA Connect Data standard v3.3 (the "FIFA Data Standard" package) as an interoperability layer: fixtures, phases, scores, teams and goal events are exported in the FCD model (namespace http://fifa.com/fc) and validated against the genuine FCD XSDs — all three exports are valid.

Exports: featured match · Premier League season (380) · WSL season (132) · full mapping in the repo at src/fds/README.md.

Honest scope: FCD is a registration & competition-administration standard. Scores live in Phase elements (the only place its model carries them); season matches therefore carry a single 2H phase with the cumulative full-time score — no half-time split is invented. MatchEvent is emitted only for goals, the one FCD event nature our stream contains; lineup Player elements are omitted rather than fabricated (FCD requires shirt number / captain / goalkeeper flags we don't generate). Our telemetry events (passes, pressure, coordinates, xT) have no FCD equivalent and remain our documented JSON extension. Identifiers are synthetic 7-character IDs with an SYN prefix — not real FIFA IDs — and match status is Played, never Officialised. This is an alignment to the published model, not a FIFA-certified integration.

The models (exactly what runs, no black boxes)

Poisson goals model. Every fixture's expected goals come from club attack/defence ratings: λhome = 1.42 × attackhome ÷ defenceaway, λaway = 1.12 × attackaway ÷ defencehome (1.42/1.12 are the league-average home/away baselines). Season results are Poisson draws on those λ values; the demo's what-if panel recomputes win/draw/win probabilities live from any λ pair using two independent Poisson distributions.

Expected threat (xT), simplified. Each event carries synthetic pitch coordinates (105×68). The threat of a location is xT(x, y) = 0.38 · e−d/24 · (1 − 0.45·|y−34|/34), where d is the distance to the goal centre — an analytic surface peaking near goal and decaying with distance and width. ΔxT for a pass is xT at the ball's new location minus xT at its previous one. Shot xG (model) = min(0.95, 2.2 × xT at the shot location). These are deliberately simple, fully documented stand-ins for learned xT/xG models — the formulas are the product, not a fitted black box.

Positions & Voronoi. Key events (shots, corners, 35m+ passes) carry a snapshot of all 22 players: each team's formation template shifted toward the ball and jittered from the same seeded stream. Voronoi zones are computed in the browser by half-plane clipping — real geometry on synthetic positions, labelled as such.

Performance numbers. Any timing shown in the Tactical Lab is measured live in your browser with performance.now(). We never display invented throughput or latency figures.

Reproduce it

git clone the repo → python3 -m unittest discover -s tests (11 tests, no installs) → python3 tools/build_demo_data.py && python3 tools/build_season_data.py → open docs/ over any static server. Azure: infra/deploy.sh with your own subscription.
